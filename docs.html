03資料怎麼統整

原始資料是 event 表，每一列是「某組、某工站、某件產品」的一次作業。

欄位意思範例有沒有用到
group_id組別G23分組
product_id產品編號，前綴是批次TEST1-P01分批次、算完成件數
station_id工站ST01–ST09分工站
start_time / finish_time開工／完工時間2026-11-14T13:16:46經過時間、偵測新資料
duration_sec作業秒數（Cycle Time）64.1各站平均 CT
status作業狀態COMPLETED只取已完工
wip_before_start / wip_after_finish站前齊套數／完工後累計9999 / 1尚未使用

統整步驟

  1. 篩選：只保留 status = COMPLETED 的紀錄。
  2. 決定批次：從產品編號取出前綴。TEST1-P01 → TEST1，TEST2-P03 → TEST2，沒有 - 的 P01 → 正式（FORMAL）。
  3. 切成產線：依「組別 + 批次」分組，每一組合是一條獨立的產線。G23 有 TEST1、TEST2 兩次練習，就是兩條線，因為不同次練習的熟練度不同，混在一起算沒有意義。
  4. 再分工站：每條線依 station_id 收集所有作業秒數。
  5. 決定最後一站：所有資料裡編號最大的工站（目前是 ST09），用來判斷「完成」。

全部組別的統整

項目算法在哪裡算
產出率最高每小時產出最大的線（同分比完成件數）Python
平均平衡率所有線的平衡率取平均網頁
排名依每小時產出由高到低排序。選了批次時只跟同批次的組比網頁

工業工程的意思：瓶頸站決定整條線的速度，最慢那站做不完，後面的站只能等。平衡率越接近 100%，各站工作量越平均；越低代表有的站很忙、有的站在等。

為什麼「完成」要做到最後一站：測試資料中 G20 只做了 ST01 一站，如果把它自己的最後一站當完成，會被算成每小時 1011 件。改成以整條線的最後一站（ST09）判斷後，沒做完的線產出為 0。

按鈕Python 做的事
開始模擬建立新的 Run ID，執行次數歸零，啟動迴圈
暫停模擬停止迴圈，但保留執行次數、Run ID；記下暫停時間
繼續模擬從暫停的地方接著跑；暫停的時間不算進 90 分鐘
停止模擬結束這次模擬，下次按開始才從頭來

Render 休眠醒來時記憶體是空的，所以啟動時會先讀一次資料庫、算一次「啟動時的資料快照」，網頁一打開就有資料。

③ 單一產線的指標

simulation.py analyze_line()
def analyze_line(rows, final_station):
    # 依工站收集作業秒數
    by_station = defaultdict(list)
    for r in rows:
        if r.get("duration_sec") is not None:
            by_station[r["station_id"]].append(float(r["duration_sec"]))
    stations = sorted(by_station)
    avg_ct = {s: round(statistics.fmean(v), 1) for s, v in by_station.items()}

    # 開工 / 完成的產品（集合 = 不重複計算）
    started  = {r["product_id"] for r in rows if r["station_id"] == stations[0]}
    finished = {r["product_id"] for r in rows if r["station_id"] == final_station}

    elapsed = (max(完工時間) - min(開工時間)).total_seconds()

    bottleneck = max(avg_ct, key=avg_ct.get)            # 平均 CT 最大的站
    max_ct = avg_ct[bottleneck]
    balance = sum(avg_ct.values()) / (len(avg_ct) * max_ct)

    return {
        "avg_ct": avg_ct, "bottleneck": bottleneck, "bottleneck_ct": max_ct,
        "balance_pct": round(balance * 100, 1),
        "finished": len(finished),
        "wip": max(len(started) - len(finished), 0),
        "throughput_per_hr": round(len(finished) / elapsed * 3600, 1),
        ...
    }

# Supabase 一次最多回 1000 筆，分頁讀完
async def fetch_events(self, table, limit=20000):
    rows = []
    while len(rows) < limit:
        page = await self._get(table, {"order": "finish_time.asc", "limit": 1000, "offset": len(rows)})
        rows += page
        if len(page) < 1000: break
    return rows

def make_store():
